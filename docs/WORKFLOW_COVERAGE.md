# 工作类型与本轮意见覆盖

设计依据为可访问的 DSH/Codex 人类任务请求、工作文件目录和代表性文档/模型的工作结构。目录枚举和任务类型归纳不等于通读全部原文；公开源码不保留私有任务历史或交易资料。附带材料内的指令只是研究内容，不是本次操作授权。

研究与会议是主干；项目是持续组织同一研究对象的材料、版本、证据、模型和交付的容器。它们共享首页，避免重复导航。技术问题、邮件、交易文件和模型是主干中的实际工作目的，不能只有“Memo/纪要”两类成品。

| 用户意见/任务 | 当前路径与结果 | 明确边界 |
|---|---|---|
| 合并首页和项目库 | 研究首页内公司档案与完整项目材料库 | 项目关系保留 |
| 友好阅读、合并AI输入 | 安全Markdown排版；研究页单一输入区选择问答/生成/行动 | 编辑保留原文本 |
| 子任务、自动分类和多版本 | 导入/创建/修改/迁移自动分组；自定义子任务；版本族展开 | 本机规则；模糊材料归项目资料；不认定获批终版 |
| 基本问题研究/技术HTML | 研究简报、技术解释/路线比较、研究问题；可编辑HTML导出 | 无联网查证时标概念草稿 |
| DD/IC Memo/Word与PPT | 按研究目的生成同一有来源正文，继续编辑后分别导出 | 草稿；不等于完整机构模板deck或已完成DD |
| 讨论材料 | 议题→证据→经营/投资含义→待决问题 | 尊重用户页数和受众；不补造数据 |
| 邮件/专家request | 简洁请求、版本用途、专家背景筛选和核心问题 | 保存草稿；不发送、不虚构承诺 |
| 访谈问题 | 缺口→问题→为什么问→对象→优先级 | 必须明确选取材料 |
| 会议表格整理 | 会议结构化纪要；表格纪要/专家对照purpose | 保留分歧和归属，多个版本非独立专家 |
| Excel建模 | P/E、P/S、DCF、单层债务LBO；保存重开、情景比较、动态公式XLSX | 完整三表/多层债务/任意导入表自动修改仍待实现 |
| 复杂Excel审阅 | 抽取模型证据→驱动、口径、公式证据和缺口检查 | 不运行宏、不以缓存值假装原生重算 |
| 协议/notes/版本差异 | 自动材料分组；协议审阅、所选版本内容对照 | 不是法律意见；保留原版本 |
| 项目更新 | 已选材料及项目研究/会议/任务记录→更新草稿 | 登记时间不等于本周业务变化 |
| 每次修订发布 | 自动SOP隔离测试→备份→本地/隧道验证→push→SHA确认 | 云端CI另核对；同步时间非云上传完成证明 |

工作流明确展示每份选定材料提供多少文字、哪些只有摘录；来源与覆盖随草稿保存。缺输入、失效资料、越界来源、无引用/无正文或模型不可用时给出具体错误，不以空大纲冒充交付。任务历史中与投资软件无关的个人、娱乐和系统维护请求不增加为主导航，仍可通过通用研究/草稿目的处理适用部分。
